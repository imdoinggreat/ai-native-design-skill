# 用动效引导注意力

涉及动画、镜头移动、界面过渡或动态讲解时阅读本指南。

## 先设计节拍，再添加效果

为每一拍明确以下信息：

| 字段 | 要回答的问题 |
|---|---|
| 时间范围 | 何时开始、稳定、结束？ |
| 注意力焦点 | 观众此刻应该注意哪一个重点？ |
| 信息或动作 | 观众需要理解什么或做什么？ |
| 阅读停留 | 内容保持稳定多长时间？ |
| 过渡目的 | 运动为什么有助于理解？ |
| 连续性 | 哪个对象、位置或关系连接前后状态？ |
| 减少动态效果版本 | 没有运动时如何传达同样的信息？ |

依据实际文案、受众和播放环境估算时间，并按正常速度检查。标签、图表、陌生术语和译文不能统一套用每秒阅读字数。

让相互竞争的运动依次发生，给注意力转移留出空间。如果多个元素构成同一个感知整体，可以同时运动；此时应说明共同焦点，不必禁止一切同步动画。

过渡中保留对象身份与空间关系。镜头表现不能隐藏目标、让人迷失方向，或成为访问内容的唯一入口。交互场景保留键盘操作和直接导航；被动播放的视频要保证文字可读，静音时也能理解主要信息。

## 普通功能示例：导出 CSV

假设产品已支持导出当前筛选后的表格；展示前需确认此行为。下列数据场景仅作示意。

| 时间 | 焦点与信息 | 运动、停留与连续性 |
|---|---|---|
| 0–4 秒 | 筛选后的表格：“把当前视图带走。” | 短暂突出选中内容，然后稳定停留供阅读。 |
| 4–8 秒 | 导出控件：“导出 CSV。” | 将注意力移向真实控件，表格保持静止。 |
| 8–13 秒 | 下载文件：“筛选后的行，保存为文件。” | 表格标题延续到文件标签，再停留。 |
| 13–17 秒 | 在电子表格中打开相同的行 | 保持列名与数值一致，画面稳定后再阅读。 |
| 17–20 秒 | 最终动作：“导出当前视图。” | 回到产品控件，停留在结尾画面。 |

播放检查停留时间是否足够；优先精简文案，不要不断加快节奏。如果任务涉及空结果、失败或大文件导出，应准确呈现。没有证据时，不得暗示瞬时处理或节省多少时间。

减少动态效果的版本使用稳定画面与简单切换，保留相同信息顺序。分别判断观众是否理解导出了什么、文件去了哪里，以及画面是否有表现力。
